# 0.1.0 修复与补完工作区

本目录是 P0～P2 后续修复和补完工作的唯一追踪入口。原有创意、路线图、技术栈、P0/P1/P2 文档及整体审查报告均作为冻结基线保留，不在本工作区的实施过程中回写。

## 文件

- [overall-design-review.md](./overall-design-review.md)：触发本轮修复工作的整体审查报告，正文作为冻结证据保留。
- [tracker.md](./tracker.md)：所有问题、缺口、优先级、依赖与验收条件。
- [worklog.md](./worklog.md)：按日期记录每次实施、验证结果和状态变化。

## 边界

### 允许变更

- 本目录下的追踪记录。
- 当前追踪项明确列出的业务代码、测试和必要配置。
- 为验证当前追踪项产生的测试代码。

### 冻结内容

- `docs/brainstorm.md`
- `docs/roadmap.md`
- `docs/tech-stack.md`
- `docs/active/0.1.0/p0-engineering-base/`
- `docs/active/0.1.0/p1-map-photos/`
- `docs/active/0.1.0/p2-album/`
- `docs/active/0.1.0/remediation/overall-design-review.md`（正文冻结）

冻结内容只作为证据读取。需要修正旧结论时，在本目录新增更正记录；除非用户以后明确解除冻结，否则不修改上述文件。

## 工作规则

1. 同一时间最多一个条目处于 `in-progress`。
2. 开始前在 `tracker.md` 更新状态，并在 `worklog.md` 写明基线。
3. 只修改当前条目完成标准所需的文件。
4. 功能或缺陷修复采用测试先行；至少保留失败与通过证据。
5. 验证必须使用 fresh 命令输出，不能引用“应该通过”。
6. 条目只有在完成标准全部可判定通过后才能标记 `verified`。
7. 新发现不得塞入当前条目；应分配新 ID 后进入队列。
8. 每次状态变化都追加工作日志，不覆盖历史记录。

## 状态定义

| 状态 | 含义 |
|---|---|
| `queued` | 已登记，尚未开始 |
| `in-progress` | 当前唯一正在实施的条目 |
| `blocked` | 存在明确阻塞条件，日志中必须说明原因 |
| `verified` | 完成标准全部通过并记录验证证据 |
| `superseded` | 被另一个明确条目替代，必须记录替代 ID |
