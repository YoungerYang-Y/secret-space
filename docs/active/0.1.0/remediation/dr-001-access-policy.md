# DR-001：访问与媒体读取策略（待决）

**逻辑版本：** 0.1.0
**状态：** 已决议（方案 A）
**追踪项：** DR-001
**范围：** 只约束后续修复；不回写冻结的 P0～P2 文档。

## 结论先行

当前 API 的角色校验已覆盖内容元数据读取和管理写入，但上传接口会返回可直连的 R2 `publicUrl`。若对象存储公开，图片字节不再受 API 角色校验保护。

推荐把照片和相册媒体定义为私有内容：R2 桶保持私有，服务端只在通过角色校验后签发短期读取 URL。该方案与“私密空间”定位一致，也为后续媒体删除闭环（DR-002）提供稳定的 `storageKey`。

## 读取策略备选

### 方案 A（已选）：私有桶与短期签名读取

- R2 桶和自定义媒体域名不允许匿名读取。
- 数据库保存稳定的 `storageKey`，不把永久公开 URL 当作内容地址。
- 内容读取 API 在完成角色校验后，为当前响应所需媒体签发短期 GET URL；默认有效期建议为 5 分钟。
- 管理端的 PUT 上传签名保持短期有效（当前为 10 分钟），并继续限定为管理员。

影响：需要调整 R2 服务、照片/相册读取模型和前端消费方式；`storageKey` 的统一与删除重试由 DR-002 承接。

### 方案 B：公开媒体

- R2 桶或媒体域名允许匿名读取，数据库继续保存公开 URL。
- API 角色校验只保护元数据，不保护已泄露或被分享的媒体 URL。

影响：实现简单，但与“私密空间”目标冲突；必须在产品说明、上传提示和风险接受记录中明确“媒体可被持有链接者读取”。

## 选定方案后的实施边界

无论选择哪一项，DR-001 的实现都必须做到：

1. 为匿名、访客、所有者、管理员补齐内容读取 API 集成测试。
2. 让所有内容读取接口严格符合上表，不以客户端隐藏按钮替代服务端鉴权。
3. 在本目录补齐 Spec、Design 和测试先行的执行计划；用户确认计划后再修改业务代码。
4. 不在 DR-001 顺带实现删除重试、相册模板不变量或管理员会话迁移；这些由其各自追踪项处理。

## 决议

2026-07-18 已确认选择 **方案 A：私有桶 + 短期签名读取**。后续行为规格和设计见 [dr-001-private-media](./dr-001-private-media/)。
