# 媒体删除闭环

**逻辑版本：** 0.1.0
**追踪项：** DR-002
**Resolved Path:** `docs/active/0.1.0/remediation/dr-002-media-deletion/`

## Overview

管理员删除照片、相册或相册页面后，对应媒体对象最终一定从对象存储中移除；存储故障只推迟删除、不丢失删除意图，且失败过程可查询、可重试。删除任务的对象标识来自持久化的稳定 `storageKey`，不从公开 URL 反解析。

本项显式改变一个既有语义：删除接口不再因对象存储故障返回 5xx。数据库删除与删除任务登记在同一事务提交后，接口即成功；对象存储删除由任务驱动、最终一致。这修复了「存储故障时管理员无法删除照片」与「相册/页面删除后对象永久孤儿」两个缺陷。

## Behavior: 统一删除语义

### Scenario: 管理员删除照片（存储正常）

Given 管理员已取得有效会话，某省份有一张已确认的照片
When 管理员删除该照片
Then 照片记录被删除，对象存储中对应对象被删除
And 系统中留下一条已完成的删除任务记录

### Scenario: 管理员删除照片（存储故障）

Given 管理员已取得有效会话，某省份有一张已确认的照片，且对象存储不可用
When 管理员删除该照片
Then 响应为成功而非 5xx，照片记录已被删除
And 系统中存在该对象的待重试删除任务，包含 key 与失败原因

### Scenario: 管理员删除相册

Given 管理员已取得有效会话，某相册有封面与若干页面图片
When 管理员删除该相册
Then 相册与其页面记录被删除
And 封面与全部页面图片各自登记了删除任务

### Scenario: 管理员删除相册页面

Given 管理员已取得有效会话，某页面包含两张图片
When 管理员删除该页面
Then 页面记录被删除
And 两张图片各自登记了删除任务，不再被静默遗留

## Behavior: 持久化重试

### Scenario: 存储恢复后重试成功

Given 存在一个因存储故障而待重试的删除任务
When 存储恢复后执行重试
Then 对象被实际删除，任务状态变为已完成
And 任务保留处理次数与时间记录

### Scenario: 持续失败的任务

Given 一个删除任务重试多次仍然失败
When 查询该任务
Then 任务保持未完成状态，包含累计尝试次数、最近一次错误与下次可重试时间

### Scenario: 服务重启不丢失待重试任务

Given 存在待重试的删除任务，随后服务进程重启
When 服务再次启动
Then 待重试任务仍然保留并被再次尝试

### Scenario: 重复删除幂等

Given 同一对象 key 出现在多条删除任务或多次重试中
When 对象已被删除后再次执行删除
Then 不抛出错误，任务正常标记完成

## Behavior: 失败可观测

### Scenario: 管理员查询删除任务

Given 管理员已取得有效会话，存在已完成、待重试或持续失败的任务
When 管理员查询删除任务列表
Then 响应包含每条任务的 key、状态、尝试次数、最近错误与时间

### Scenario: 非管理员访问任务接口

Given 匿名请求，或访客、所有者会话
When 查询删除任务列表或触发重试
Then 匿名返回 401，访客与所有者返回 403

## Behavior: 受控对象标识

### Scenario: 任务 key 来自持久化引用

Given 一条已保存的照片、相册封面或页面图片
When 系统登记其删除任务
Then 任务 key 来自数据库中持久化的 `media://` 引用或照片的稳定 `key` 列
And 不接收、不解析任何公开 URL 或客户端提交的对象标识

### Scenario: 历史引用已迁移

Given DR-001 的历史引用迁移已在部署中完成（dry-run 零失败 + apply）
When 删除任一迁移前保存的媒体
Then 删除任务 key 与上传时写入的逻辑 key 一致

## Behavior: 未确认上传的孤儿对象

### Scenario: 未确认上传自动清除

Given 一个已取得上传签名但超过上传签名有效期仍未确认的对象
When 到达对象存储生命周期规则设定的期限
Then 该对象由桶级生命周期规则自动清除，无需应用介入

## Constraints

- 删除接口在数据库删除与任务登记提交后即成功，不因对象存储故障返回 5xx；此语义变化适用于照片、相册与页面的全部删除路径。
- 数据库删除与删除任务登记必须在同一数据库事务内完成，防止出现「记录已删、任务未登记」。
- 删除任务的 key 只能来自持久化的 `media://` 引用或照片 `key` 列；不得从公开 URL 反解析，不得接受客户端提交的对象标识。
- 删除对象操作必须幂等；同一批次内相同 key 只登记一次。
- 失败任务的状态、尝试次数、最近错误必须持久化并可由管理员查询，不允许只写进程日志。
- 重试机制不引入新的运行时依赖（不新增定时任务框架）；以服务启动清扫与管理员手动触发为重试入口。
- 任务记录与日志不得包含签名 URL 或任何可直接读取媒体的凭据。
- 未确认上传对象的清理由桶级生命周期规则承担，属于部署配置，不在应用代码中实现列举或扫描。
- 本项不处理：相册模板不变量（DR-005）、管理员会话方案（DR-003）、存储供应商切换（沿用 DR-001 的 30 天双读方案）。
